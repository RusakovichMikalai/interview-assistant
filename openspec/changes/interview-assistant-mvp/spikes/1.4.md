# Spike 1.4 - warm `claude -p` stream-json: TTFT and limit/reset format

Goal: capture the real `claude -p` stream-json wire shapes so the provisional ones
in `claude-subscription.ts` can be replaced, plus warm TTFT and the exact limit /
reset-time payload.

Status: DONE (live run 2026-11-27, Linux). Adapter updated to the captured shapes.

## How to run

On a machine with `claude` logged in and network (not the sandbox):

```
node openspec/changes/interview-assistant-mvp/spikes/spike-1.4.mjs
```

For a real limit payload, run while the subscription is at/near its cap. The full
output is written verbatim to `spikes/raw.jsonl`.

## Results

- claude CLI version: `2.1.332`, Node v22.22.3
- Model used by `claude -p` here: `claude-opus-5-5` with extended thinking ON.
- TTFT warm (manual, write -> first assistant text), 5 serial warm requests,
  CLI-default model (opus-5-5 + thinking): p50 = 3160 ms, p90 = 4768 ms.
  Per request: 4768, 3160, 3944, 2619, 2002 ms. Cold 4768 ms, warms to ~2000 ms.
- Model comparison with `--model` forced and thinking off (re-run 2026-11-27,
  `MODEL=... REQUESTS=4 node spike-1.4.mjs`), 4 warm turns each:
  - sonnet (`claude-sonnet-5-5`): TTFT 604, 189, 85, 92 ms -> p50 189, p90 604.
  - haiku (`claude-haiku-5-5`):  TTFT 599, 194, 85, 84 ms -> p50 194, p90 599.
  - opus (`claude-opus-5-5`):    TTFT 595, 191, 87, 75 ms -> p50 191, p90 595.
  All three have the SAME warm TTFT: first-token latency is network/CLI bound,
  not model-bound, once extended thinking is off (forcing `--model` turns it off;
  the CLI-default opus path above kept thinking on, hence its ~3160 ms). So the
  model choice is quality vs quota/tokens-per-sec, not first-token speed.
  Decision: the adapter forces `claude-sonnet-5-5` (best quality/quota balance at
  equal latency). haiku = override to conserve quota; opus = override for max
  quality when quota is plentiful (burns it fastest, slowest to finish a hint).
- CLI self-measured on the `result` event: `ttft_ms` 3362, `ttft_stream_ms` 2639
  (= `first_content_frame_ms`), `time_to_request_ms` 122. Prefer these over the
  manual stopwatch when wiring latency telemetry.
- Cache: the ~2k-token `--append-system-prompt` prefix warmed to
  `cache_creation_input_tokens` = 31072 with `ephemeral_1h` caching.
- Cost: `total_cost_usd` ~= 0.25 per request (opus + thinking). Billed to the
  subscription, not the API. Too slow and too costly for live hints -> a
  subscription preset must target a fast, non-thinking model.

### Wire shapes observed (from raw.jsonl)

- Input line accepted: `{"type":"user","message":{"role":"user","content":[{"type":"text","text":"..."}]}}`
- Assistant text event (one full message per line, not deltas; thinking arrives as
  a separate `thinking`-only content item that carries no text):
  `{"type":"assistant","message":{"model":"claude-opus-5-5","content":[{"type":"text","text":"Готов к работе, жду задачу."}]}}`
- Terminal event: `{"type":"result","subtype":"success","is_error":false,"result":"...","stop_reason":"end_turn","ttft_ms":3362,"duration_ms":3859,...}`
- Rate limit (PROACTIVE, not an error; emitted every turn while still allowed):
  ```json
  {"type":"rate_limit_event","rate_limit_info":{
    "status":"allowed","resetsAt":1795796400,"rateLimitType":"five_hour",
    "overageStatus":"rejected","isUsingOverage":false,
    "unifiedWindows":{
      "five_hour":{"utilization":0.37,"resetsAt":1795796400,"status":"allowed"},
      "seven_day":{"utilization":0.70,"resetsAt":1796032800,"status":"allowed"}}}}
  ```
  `resetsAt` is epoch SECONDS. A real cap was not hit on this run, so the exact
  `status` string for a block is still unconfirmed (treat any value != "allowed"
  as limited). TODO: re-run at the cap to record the blocked `status`.
- Login-required: not captured (session was logged in). The adapter maps a
  `result` with `is_error:true` whose text matches login/auth to `login_required`;
  confirm the real message on a logged-out run.
- Noise: `--allowedTools Noop` left no tool-call events; the only stray line was a
  `system/hook_response` echoing the parent session's SessionStart hook output.
  The adapter runs its own child, so this is a spike-env artifact, not a concern.
