# Spike 1.6 - Electron lists PipeWire monitor sources?

## Goal
Decide task 4.3 (Linux capture). If Electron/Chromium exposes the PipeWire/Pulse
monitor source (system output) as an `audioinput` device, the built-in
`getUserMedia` path captures interviewer audio and NO native addon is needed on
Linux. If it does not, 4.3 needs a native PipeWire capture addon.

## How to run
Real desktop session only - needs a display and a running audio server. The
sandbox has neither, so run it yourself:

```
npx electron openspec/changes/interview-assistant-mvp/spikes/spike-1.6.mjs
```

It opens an offscreen window, grants mic permission, calls `getUserMedia` to
reveal device labels, enumerates `audioinput` devices and prints them with a
verdict. Exit code: 0 = monitor input found, 1 = none, 2 = no permission / no
audio server.

Cross-check at the PipeWire level (the monitor should exist regardless of what
Electron shows):

```
pactl list sources short | grep -i monitor
wpctl status
```

## Results
Machine: Linux Mint 22.3 (Ubuntu 24.04 base), PipeWire + WirePlumber, X11,
Node v22, Electron from node_modules.

| run | audioinput count | monitor inputs | verdict |
|-----|------------------|----------------|---------|
| 1   | 4                | 0              | no monitor -> native addon needed |

Raw `audioinput` labels (Linux Mint 22.3, PipeWire, Electron 33.4.11):

```
Default            [default..]
LifeCam HD-3000 Mono   [c514a2fcd1bd..]
Family 17h/19h HD Audio Controller Analog Stereo   [02692a321fa9..]
Virtual            [5f569b4beac6..]
```

Labels are populated, so mic permission was granted - the absence of a monitor
input is real, not a permissions artifact. Chromium on PipeWire does not surface
the sink monitor as a getUserMedia input.

## Decisions
getUserMedia alone CANNOT capture interviewer (system-output) audio on Linux
(PipeWire). Task 4.3 needs a native capture path from the PipeWire/Pulse monitor
source - not the browser enumeration. The mic channel can still come from
getUserMedia; only the system-output channel needs the native path.

## Sandbox note
Not runnable in the agent sandbox: no display and no audio server. Agent writes
the script; user runs it on the live session and pastes the output.
